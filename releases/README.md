# Release notes

One file per version, named `v<version>.md` (for example `v2.2.0.md`). The
**Release** workflow creates the GitHub release from that file, so the notes
must be merged to `main` before releasing. The file's contents become the
release body verbatim, so write them for someone running `npx brignano`: lead
with what they can now do, and leave repo hygiene to commit messages.
